# zalupa228local

Локальный голосовой чат в браузере: WebRTC mesh + WebSocket signaling + текстовый чат.

Текущий бэкенд написан на Go. При доступной MongoDB история сообщений хранится в базе; при недоступной Mongo сервер автоматически уходит в in-memory режим (до перезапуска процесса).

## Требования

- Go 1.23+
- Браузер с поддержкой WebRTC (Chrome/Edge/Firefox)
- **MongoDB** (опционально для Go-сервера): если недоступна, используется in-memory чат; для постоянного хранения — `docker compose` или локальный Mongo

## Быстрый запуск локально (без Docker)

1. Откройте терминал в каталоге проекта `zalupa228local` (или в папке с этим репозиторием).
2. (Опционально) Запустите MongoDB или задайте **`MONGODB_URI`**. Без БД сервер всё равно поднимется.
3. Запустите сервер:
   - `go run ./cmd/server`
4. Сервер поднимется на порту `3000` (или в `PORT`, если задана переменная окружения).
5. Дополнительно поднимается **HTTPS** на порту `3443` (или `HTTPS_PORT`, если задана). Используйте его для доступа с других устройств в сети — микрофон в браузере требует **HTTPS** или `localhost`.
6. **Админ-панель** (исключение участников): пароль по умолчанию `admin123`; в проде задайте **`ADMIN_PANEL_PASSWORD`** в окружении.

## Переменные окружения

- `PORT` (по умолчанию `3000`)
- `HTTPS_PORT` (по умолчанию `3443`, `0` отключает HTTPS)
- `LISTEN_HOST` (по умолчанию `::`, dual-stack IPv4/IPv6)
- `MONGODB_URI` (по умолчанию `mongodb://127.0.0.1:27017/zalupa228local`)
- `ADMIN_PANEL_PASSWORD` (по умолчанию `admin123`)
- `CERT_EXTRA_IPS` (доп. IP для SAN self-signed сертификата, через запятую)

## Почему локально есть звук, а на VPS может не быть

Голос здесь работает не через медиасервер на VPS, а как `WebRTC mesh`:

- Go-сервер на VPS делает только `WebSocket signaling`
- сам звук идёт напрямую `браузер <-> браузер`
- поэтому локально всё может работать без проблем, а через интернет ломаться на NAT/CGNAT/firewall

Если страница открывается, чат работает, а аудио между удалёнными клиентами не поднимается, почти всегда проблема в `ICE/TURN`, а не в Go-бэкенде.

Признаки:

- участники видят друг друга в комнате, но не слышат
- в списке участников статус зависает на `подключение` или переключается в `нет p2p`
- локально в одной сети всё работает, а через мобильный интернет/домашний интернет уже нет

## VPS: как поднимать нормально

Для VPS нужен рабочий `TURN`, лучше свой `coturn`, а не только публичный relay.

В репозитории есть профиль compose `turn`. Для запуска на VPS задайте переменные окружения:

- `TURN_PUBLIC_IP` — публичный IP VPS
- `TURN_REALM` — домен или имя хоста
- `TURN_USERNAME`
- `TURN_CREDENTIAL`
- `TURN_URLS`, например `turn:your-domain:3478?transport=udp,turn:your-domain:3478?transport=tcp`

После этого запускайте:

- `docker compose --profile turn up --build`

И откройте наружу:

- `3478/tcp`
- `3478/udp`
- диапазон UDP relay-портов `49160-49200` или свой диапазон из `TURN_MIN_PORT` / `TURN_MAX_PORT`

Важно:

- если `TURN_URLS` не задан, браузер использует только STUN + публичный best-effort relay
- для реального продакшена этого часто недостаточно
- сама VPS не становится аудиомостом автоматически только потому, что приложение запущено на ней

## Подключение клиентов

На этом же ПК:

- `http://localhost:3000` или `http://127.0.0.1:3000`

С другого телефона/ПК в той же сети:

- `https://<host-ip>:3443`

HTTP по LAN-IP обычно откроет страницу, но микрофон браузер часто блокирует без HTTPS.

## Как использовать

1. Введи уникальный `nickname` и нажми `Join`.
2. Разреши доступ к микрофону.
3. Кнопка микрофона включает/выключает отправку аудио.
4. В списке участников можно локально выключить звук конкретного собеседника.
5. В чате доступны сообщения, редактирование, удаление и реакции.

## Docker (приложение + MongoDB)

Нужны [Docker](https://docs.docker.com/get-docker/) и Docker Compose.

Из корня проекта:

- `docker compose up --build`
- или скрипт **PowerShell (Windows):** `.\scripts\run-docker.ps1`
- или **Linux/macOS:** `chmod +x scripts/run-docker.sh` и `./scripts/run-docker.sh`

Порты приложения наружу: `3000` (HTTP) и `3443` (HTTPS). Mongo доступна только внутри сети compose.

Если нужен доступ с телефона по `https://<LAN-IP>:3443`, добавь LAN IP в сертификат:

- PowerShell: `.\scripts\run-docker.ps1 -LanIp 192.168.0.199`
- bash: `LAN_IP=192.168.0.199 ./scripts/run-docker.sh`
- вручную через `CERT_EXTRA_IPS`

## Smoke test WebSocket

Есть небольшой локальный тест:

- `go run ./tools/ws_smoketest`

Он проверяет базовый поток: `hello -> join -> chat-history -> chat -> react -> edit -> delete`.
